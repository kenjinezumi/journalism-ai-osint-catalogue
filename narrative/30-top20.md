## The 20 projects to examine first

This is a curated shortlist, not the top 20 by score. It is ordered by what I would actually do
first, and it deliberately includes two items that score lower because they close a gap nothing
else covers.

| # | Project | Why first |
|---|---|---|
| 1 | **Dangerzone** (SUR-B3-03, 92) | Nothing else protects you at the point of first contact with an unknown document. Automate it at ingest before adopting anything else in the document pillar. |
| 2 | **ICIJ Datashare** (JAI-A2-25, 92) | Desktop mode is the shortest path from "we received a dump" to "reporters are searching it" with no infrastructure. Try it before considering OpenAleph. |
| 3 | **OpenAleph** (JAI-A2-35, 93) | If your investigations are entity-centric, this is the platform — and this session settled the fork question: OpenAleph released 5.4.0 on 2026-11-16, upstream Aleph last released 4.1.7 in October 2025. |
| 4 | **whisper.cpp + Buzz** (JAI-A2-59 / JAI-A2-05) | A single binary and a desktop app that together stop interviews being uploaded to cloud transcription. The behavioural change is the point. |
| 5 | **SecureDrop** (SUR-B3-01, 92) | If you solicit documents from sources at real risk, this is the standard. Adopt it properly or say publicly what you do not offer. |
| 6 | **mat2** (SUR-B3-07, 94) | Metadata stripping on the publication path. Two open issues, release 0.15.0, and it prevents a failure that has burned sources. |
| 7 | **x-ray** (JAI-A4-23, 86) | Sweep incoming documents for failed redactions, and sweep your own before release. Both directions matter. |
| 8 | **FreshRSS + RSSHub** (JAI-A1-03 / JAI-A1-05, 94 / 91) | The cheapest substantial monitoring capability in the catalogue. Self-hosted, so your feed list is not a product dataset. |
| 9 | **llama.cpp + Ollama** (JAI-A3-01 / JAI-A3-02, 96 / 94) | One GPU host with an OpenAI-compatible endpoint makes "does this document leave the building" an infrastructure decision taken once. |
| 10 | **browsertrix-crawler + ReplayWeb.page** (OSINT-C1-29 / OSINT-C1-32, 94 / 94) | Capture that holds up and replay that a lawyer can open from a single file with no software. |
| 11 | **Scoop** (OSINT-C1-36, 90) | Provenance-attested capture for the specific pages a story cites. Verify the signing format with Harvard LIL before relying on it legally — this survey did not. |
| 12 | **EFF Rayhunter** (SUR-B3-13, 88) | Makes IMSI-catcher detection possible on tens-of-dollars hardware. Baseline before treating anomalies as detections. |
| 13 | **OpenSanctions + yente** (OSINT-C3-01 / JAI-A2-61, 94 / 84) | Screening on your own infrastructure so you do not tell a vendor whom you are investigating. Settle the CC-BY-NC data licence in writing first. |
| 14 | **Splink** (JAI-A2-48, 86) | Replace dedupe. Auditable match weights are the difference between a defensible linkage and an assertion. |
| 15 | **bellingcat/osm-search + streetlevel** (OSINT-C2-27 / OSINT-C2-32, 88 / 82) | The two halves of practical photo geolocation. Note that streetlevel uses providers' internal interfaces and discloses your coordinates. |
| 16 | **ShadowFinder** (OSINT-C2-17, 91) | Physics-based falsification of a claimed time and place. Use the local CLI, not the documented Colab route. |
| 17 | **CryptPad** (SUR-B3-27, 92) | Replaces the shared planning document on a third-party cloud — the most common and least-discussed leak in investigative work. |
| 18 | **Datasette + DuckDB** (JAI-A2-09 / JAI-A1-19, 93 / 86) | Fastest route from extracted data to something reporters can search, and from a large file to SQL on a laptop. |
| 19 | **Haystack** (JAI-A3-05, 86) | If you build document question-answering, build it on an auditable pipeline with built-in evaluation. Measure faithfulness before anyone relies on it. |
| 20 | **PMTiles + MapLibre** (JAI-A1-24 / JAI-A1-22, 87 / 87) | Self-hosted map publishing with no tile server and no third-party provider watching your readers. Build the pipeline once. |

Two deliberate inclusions below their score: **Rayhunter** (88) and **Scoop** (90) rank outside
the top 20 by points but close capability gaps nothing else in the catalogue covers.

Two high scorers deliberately *not* in the shortlist: **mitmproxy** (96) and **ExifTool** (96)
are superb and you almost certainly already have them — they rank first on ubiquity and
reliability, which is exactly why they need no examination.
