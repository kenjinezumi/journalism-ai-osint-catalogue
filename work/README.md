# Working data and provenance

This directory holds the raw verification output and the scripts that produced it. It is
committed because `meta.jsonl` is the **primary maintenance evidence** behind most assessments
in the catalogue, and because keeping the tooling alongside it makes the verification
reproducible.

Nothing here is generated by `build.py`, and nothing here is read by it.

## Verification output

| File | Contents |
|---|---|
| `meta.jsonl` | GitHub REST API metadata for 583 candidate repositories, captured 2026-11-17. One JSON object per repository: queried path, canonical `full_name`, a `renamed` flag, SPDX licence, `archived`, `disabled`, `pushed_at`, `created_at`, stars, forks, open issues, language, fork parent, homepage, description, topics, latest release tag and date, latest tag. Because the REST API follows renames, the `full_name` field is what revealed the 22 repository transfers recorded in [`../sources/evidence/leads.md`](../sources/evidence/leads.md). |
| `candidates.txt` | The 583 candidate repository paths that were swept, assembled from the first session's discovery lists plus every repository URL already in the recovered inventory. |
| `inventory.json` | The first session's five recovered JSONL files consolidated and deduplicated — 185 rows, 184 unique projects after the ThreatExchange double-count was corrected. |
| `A2.jsonl` … `C2.jsonl` | Working copies of the recovered per-segment records. The untouched originals are preserved in [`../sources/recovered/cat/`](../sources/recovered/cat/); these copies exist so `consolidate.py` can be re-run in place. |
| `dump_A2.txt` … `dump_C2.txt` | Per-segment joined views (recovered record fields alongside the fresh API metadata) used while authoring the assessments. Derived; regenerate with `join.py`. |
| `need.txt` | Candidate list used to find which planned projects still lacked metadata. |

## Scripts

| Script | Purpose |
|---|---|
| `sweep.py` | Threaded GitHub API sweep over `candidates.txt`, writing `meta.jsonl`. Requires an authenticated `gh` CLI. |
| `sweep.sh` | Earlier shell version of the same sweep, superseded by `sweep.py` (its inline JSON handling was unreliable). Kept for provenance. |
| `probe.py` | Ad-hoc probe of specific repositories, printing licence, archive status, release and fork parent. Used to resolve individual leads. |
| `show.py` | Prints a one-line metadata summary per repository from `meta.jsonl`. |
| `join.py` | Joins a recovered segment's records to the fresh metadata, producing the `dump_*.txt` views. |
| `consolidate.py` | The first session's dedupe-and-stable-ID script, with its verified renames and forks maps. Working copy; the original is in `../sources/recovered/cat/`. |
| `checklinks.py` | Validates every relative markdown link and in-page anchor across the repository, using the same heading-slug algorithm as `build.py`. Run it after any build: `python3 work/checklinks.py` (exit status 1 if anything is broken). |

## Re-running the verification

```sh
gh auth status                 # the sweep needs an authenticated GitHub CLI
python3 work/sweep.py          # rewrites work/meta.jsonl
```

The sweep takes roughly ten minutes for 583 repositories at twelve concurrent workers. Diff the
result against the committed `meta.jsonl` to see what has changed since 2026-11-17 — the
projects classified "Maintenance appears to be declining" are where a catalogue of this kind
goes stale first.
